How to Handle a Remote Developer Take-Home Task

Remote teams lean on take-home tasks because they cannot watch you work. The task is not just a coding filter: it is a test of how you deliver work asynchronously. Most candidates fail on the delivery, not the code. This page covers how to scope the task, manage the time, and deliver a package that reads well without you in the room.

Scope it before you write code

Read the task twice and list every requirement as a checklist. Then decide, in writing, what is core, what is a stretch goal, and what you will skip. Tell the team your plan in one paragraph before you start: "I will implement A and B fully, add tests for A, and skip C because of the suggested time limit." Teams score a delivered plan higher than an unfinished everything.

Respect the time limit

If the task says four hours, spend about four hours. Spending twenty signals poor judgment, and reviewers can tell. Track your time and stop when it runs out. Write down what you would do next with more time; that sentence shows senior judgment and costs you nothing.

The README decides the first impression

Before your code is read, the README is read. It needs four things:

  1. How to run it: exact commands, one line each, from a clean machine. Say the Node or Python version.
  2. What is done: your checklist from the scoping step, marked complete or skipped with reasons.
  3. Decisions: two or three sentences on the trade-offs you made and why. This is where seniority shows.
  4. What you would do next: the improvements you did not have time for.

Deliver like you are already on the team

Ship a clean repository: no dead files, no commented-out blocks, no personal config. Small commits with clear messages, not one giant commit. Handle the obvious errors, and state your assumptions instead of silently guessing. If the task leaves a requirement vague, write the assumption in the README rather than asking a question that delays you.

After you deliver

Send the link with a three-line message: what you built, where to start, and when you are available to discuss. Then wait. A good delivery usually gets reviewed within the same week; the free follow-up email guide covers what to do if it goes quiet.

Before any of this: check the role is real

Take-home tasks cost real hours, so spend them only on roles that fit you.
